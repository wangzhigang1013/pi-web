# 0006 — 代理开关只改当前进程，不写 Pi 的 settings.json

## Status

Accepted.

## Context

Pi Web 自身不读 `~/.pi/agent/settings.json` 的 `httpProxy`：那是 pi 命令行
`main()` 里的 `applyHttpProxySettings()` 干的事，Pi Web 用的是自己的
`lib/http-dispatcher.ts`。所以用户在配置文件里填的 `httpProxy` 对 Pi Web 毫无
影响，而"用国外模型时超时"却发生在 Pi Web 里 —— 用户会以为配置没生效。

同时，"点一下开关"这个交互天然要求即时生效：用户可能是先关掉代理软件，再回来
关开关；如果必须重启 Pi Web 才能生效，开关就失去了意义。

## Decision

1. **开关状态专属持久化到 `~/.pi/agent/web-proxy.json`**：Pi Web 重启时
   （`instrumentation-node.ts`）自动恢复上次的代理状态与地址，不再丢失记忆。
   同时坚持**不读写 `~/.pi/agent/settings.json`**：命令行 `pi` 的代理配置
   仍由用户在配置文件中独立掌握，两套运行时互不覆盖。配合「代理离线自动切回直连」
   特性，即使上次开着代理而这次重启时代理软件未启动，也会自动退回直连，零锁定风险。

2. **必须重建全局 dispatcher**：undici 的 `EnvHttpProxyAgent` 只在构造函数里读
   一次代理环境变量（`node_modules/undici/lib/dispatcher/env-http-proxy-agent.js`），
   单改环境变量等于没改。`setHttpProxy()` 因此每次都构造新实例并
   `undici.setGlobalDispatcher()`；模型请求走全局 fetch，下一次请求即生效，
   无需重启进程，也无需重开会话。

3. **`NO_PROXY` 必须包含本地地址**：Pi Web 用 `127.0.0.1` 访问自己的 Next 服务、
   SSE 和本机工具服务。一旦这些请求被送进代理，轻则绕远路、重则直接失败。
   `mergeLocalNoProxy()` 把 `localhost,127.0.0.1,::1` 并入用户已有的排除列表，
   而不是覆盖它。

4. **开启时校验并规范化地址**：`127.0.0.1:7897` 这类省略协议的写法要接受，
   SOCKS/PAC 要拒绝 —— pi 与 undici 都不支持它们，接受只会在运行期报一个
   更难懂的错。地址格式、端口范围、路径都在 `lib/proxy-settings.ts` 里校验。

5. **可达性与开关解耦**：`/api/proxy` 每次都探测代理端口的 TCP 连通性，但探测
   失败**不会**阻止开启。代理软件没开时开启代理确实会让所有模型请求失败，
   这正是本次改动的起因（用户"开了代理反而不能上网"）；所以 UI 必须把这个
   状态如实显示出来（绿灯/红灯 + 文案），而不是替用户拒绝或静默直连。

6. **跨组件同步、后台休眠与离线自动切回直连**：
   - **跨组件与跨标签页毫秒级同步**：`useProxySettings` 通过模块发布订阅与
     `BroadcastChannel` 保持顶栏图标、设置面板与多标签页毫秒级联动。
   - **页面后台休眠**：监听 `visibilitychange`，标签页在后台时暂停探测定时器，
     切回前台时立即探测一次，兼顾省资源与高灵敏度。
   - **代理离线时自动切回直连（设置可控开关）**：默认开启。当检测到代理软件退出
     且非刚开启状态时，自动把开关切为关闭并弹提示，彻底解决"先关软件忘关开关
     导致国内模型全挂"的顾虑。

## Consequences

- 两种运行时的代理配置各自独立：Pi Web 的开关生效不代表 `pi` 命令也走代理，
  反之亦然。这是刻意的，代价是用户要为命令行单独配置一次。
- 代理软件退出后 Pi Web 的所有模型请求都会失败（与 `pi` 命令行同样的行为），
  没有"代理不可达就自动直连"的兜底：静默直连会让"用国外模型超时"变成一个
  更隐蔽的问题。
- 探测只验证 TCP 可连接，不验证代理的转发能力。这样 Clash、v2rayN 等任何
  实现都能用，代价是端口通了但节点全挂时仍显示绿灯。
- 专属配置落盘到 `web-proxy.json`：Pi Web 重启后自动恢复上次的开关与地址（无论是开启还是关闭），免去每次重启重新点击。若重启后代理未启动，离线自动切回直连特性会自动接管切回直连。
